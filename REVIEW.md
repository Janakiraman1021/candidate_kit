# REVIEW.md

## Defects found in the starter `app/main.py`

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (line 73-74) | Never pings MongoDB. Always returns 200, even if MongoDB is down. | `GET /health` returns 200 while MongoDB is unavailable; runner rejects the service as unready. | Added `db.command("ping")` and return 503 on any exception. |
| 2 | `create_employee()` — check-then-insert (line 79-80) | Uses find-then-insert for uniqueness. Two concurrent requests with the same `emp_code` can both pass the `find_one` check and both insert, violating uniqueness. | Two simultaneous POST /employees with identical `emp_code` could both return 201. | Removed the find-one check. Rely on the unique index; catch `DuplicateKeyError` and return 409. |
| 3 | `create_employee()` — no validation (lines 53-60, 77-85) | `EmployeeIn` model has no validators. Any string is accepted for `emp_code`, `email`, `shift_start`, etc. Derived/invalid values can be stored. | Sending `emp_code: "INVALID"`, `email: "notanemail"`, or equal `shift_start`/`shift_end` all succeed with 201. | Replaced `EmployeeIn` with `EmployeeCreate` which uses `@field_validator` and `@model_validator` to enforce all contract rules. |
| 4 | `create_employee()` — naive datetime and no ms conversion (line 82, 84-85) | `created_at = datetime.now()` produces a naive (no timezone) datetime. Response returns a raw dict with `created_at` as a Python datetime object, not epoch ms. `_id` not removed before return. | `created_at` in the response is a datetime string, not an integer. API contract requires epoch ms. | Use `now_utc_truncated()` (UTC-aware). Added `serialize_employee()` to convert `created_at` to epoch ms. Pop `_id` in serializer. |
| 5 | `list_employees()` — wrong skip formula (line 93) | `skip = page * page_size` instead of `(page - 1) * page_size`. Page 1 skips `page_size` rows; page 1 returns page 2 data. | `GET /employees?page=1` returns items starting at position 21 instead of 1. | Fixed to `skip = (page - 1) * page_size`. |
| 6 | `list_employees()` — total ignores department filter (line 94) | `total = db.employees.count_documents({})` counts the entire collection regardless of the `department` filter. | `GET /employees?department=Sales` returns wrong `total`. | Changed to `db.employees.count_documents(query)` using the filtered query. |
| 7 | `list_employees()` — loads without sort and no pagination validation (lines 89-96) | No `.sort()` applied; results are in MongoDB natural order. No validation of `page >= 1` or `page_size` constraints. `created_at` not converted to epoch ms; `_id` projected out but `created_at` is a datetime. | Results are non-deterministic; `GET /employees?page=0` is not rejected with 422. | Added `.sort("emp_code", ASCENDING)`, used `Query(ge=1, le=100)` for validation, added `serialize_employee()`. |
| 8 | `compute_late_minutes()` (lines 33-37) | Uses `punch_in.replace(hour=h, minute=m, ...)` which borrows the *date* from `punch_in` in whatever timezone `punch_in` is in (naive local time). Does not use IST. Does not correctly handle the attendance date context. The floor calculation uses `total_seconds() / 60` (float) instead of integer truncation. | For IST-based shifts any punch_in stored as UTC would produce an incorrect `start` time. | Replaced with `calc_late_minutes()` which builds `shift_start_ist` from the attendance date string in IST, then computes `int(delta_seconds) // 60` for correct floor. |
| 9 | `compute_overtime()` (lines 44-47) | Does not apply the 30-minute threshold (R3). Returns any positive overtime. Does not handle overnight shifts (shift_end on next calendar day). | Overtime of 5 minutes is returned as 5 instead of 0. Overnight shift end time is placed on the punch-in calendar date, not the next day. | Replaced with `calc_overtime_minutes()` which uses `compute_shift_end_dt()` for overnight awareness and only returns minutes >= 30. |
| 10 | `punch_in()` — no 404 on unknown employee (line 101) | `emp = db.employees.find_one(...)` is not checked for None. If the employee does not exist, `emp["shift_start"]` raises `TypeError`. | `POST /attendance/punch-in` with unknown `emp_code` returns 500 instead of 404. | Replaced with `get_employee_or_404()` which raises HTTP 404. |
| 11 | `punch_in()` — naive timestamp (line 102) | `datetime.fromtimestamp(body.punched_at / 1000)` produces a naive local-time datetime. `datetime.now()` also produces a naive local datetime. Both are stored as naive datetimes in MongoDB. | Attendance date and late_minutes calculations are done in local time, not IST. Punches in non-IST environments are completely wrong. | Use `epoch_ms_to_datetime()` (UTC-aware) and `now_utc_truncated()`; connect with `tz_aware=True`. |
| 12 | `punch_in()` — date computed from local time (line 103) | `ts.date().isoformat()` uses the local OS timezone, not IST. Overnight-shift R1 logic is completely absent. | An overnight-shift employee punching in at 01:00 IST is assigned the wrong attendance date. | Replaced with `attendance_date_for_punch_in()` which converts to IST and applies R1 overnight logic. |
| 13 | `punch_in()` — check-then-insert race (lines 104-105) | Uses `find_one` then `insert_one`. Two concurrent punch-ins for the same employee/date can both pass the check and both insert. | Simultaneous duplicate punch-ins both get 201. | Removed the find-one check. Rely on unique `(emp_code, date)` index; catch `DuplicateKeyError` → 409. |
| 14 | `punch_in()` — leaks artificial `id` (line 119) | `doc["id"] = str(res.inserted_id)` adds a generated id field to the response. Contract says no id. | Response contains `"id": "<ObjectId>"`. | Removed. Use `serialize_attendance()` which never returns `_id` or `id`. |
| 15 | `punch_in()` — no status validation (line 67) | `PunchInIn.status` is `str = "PRESENT"` with no validation. Any string is accepted including `"ABSENT"`. | `POST /attendance/punch-in` with `status: "ABSENT"` succeeds with 201. | `PunchInRequest.val_status` rejects values outside `{PRESENT, WFH, ON_DUTY}`. |
| 16 | `list_attendance()` — full collection loaded into Python (line 144) | `docs = list(db.attendance_logs.find(q))` fetches all matching documents into memory before sorting, counting, and slicing. | Extremely slow and memory-intensive on ~100,000 records; fails the performance requirement. | Replaced with MongoDB `.sort()`, `.skip()`, `.limit()`; `count_documents()` for total; no Python-side sorting. |
| 17 | `list_attendance()` — wrong total (line 146) | `total = len(docs)` counts only the already-fetched page-sized result before paginating. Actually it counts all filtered docs but after loading them all, which is still wrong in the context of this endpoint. The correct total is the count before skip/limit. | `total` reports the size of the full filtered result, but only after loading all into memory. | Use `db.attendance_logs.count_documents(query)` before applying skip/limit. |
| 18 | `list_attendance()` — leaks `_id` as `id` (line 149) | `d["id"] = str(d.pop("_id"))` renames `_id` to `id` and includes it in the response. | Response contains artificial `id` field. | Removed. `serialize_attendance()` projects `_id` out and returns only contract fields. |
| 19 | `list_attendance()` — no timestamp serialization | BSON datetimes (`punch_in`, `punch_out`, history `at`) are returned as Python datetime objects, not epoch ms integers. | Response timestamps are strings like `"2026-07-06T03:58:00"` instead of integers. | `serialize_attendance()` calls `datetime_to_epoch_ms()` for all datetime fields including nested history. |
| 20 | `MongoClient` — no `tz_aware` (line 22) | `MongoClient(...)` without `tz_aware=True` returns naive datetimes from MongoDB. Naive datetimes have no timezone and can't be reliably converted to epoch ms or compared with timezone-aware datetimes. | All datetime arithmetic and IST conversions break or silently produce wrong results. | Added `tz_aware=True` to `MongoClient`. |
| 21 | No indexes at startup | The starter creates no indexes. Concurrent duplicate punch-in/employee-create relies on application-level check instead of the required unique index. Performance is O(N) on all queries. | Concurrent duplicates bypass application lock; slow queries at scale. | Added `create_indexes()` via `@app.on_event("startup")` creating all required unique and supporting indexes. |
| 22 | Missing endpoints (lines 153-162) | `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, all analytics endpoints, and `GET /admin/explain/{endpoint}` are listed as TODO but not implemented. | 7 of 12 required endpoints return 404. | Implemented all 12 endpoints from scratch. |

## Items reviewed and intentionally kept

- The `IST = timezone(timedelta(hours=5, minutes=30))` definition was correct. Kept as-is.
- The `load_dotenv()` call at module level is acceptable for local development convenience; real environment variables always win because `os.environ.get()` is called after `load_dotenv()`.
